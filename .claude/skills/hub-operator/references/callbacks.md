# Callback endpoints (registrar) and signatures

For `async_callback` integrations (and for terminal-state notifications on `wait`/`async` ones) the Hub POSTs results to the calling tenant's **registrar endpoint**: a URL + signing secret registered once per tenant and reused by many integrations (DESIGN §3.1, §12.1). Which events go where is part of each **integration version** (`webhooks`), so subscribing is a publish.

## Register a callback endpoint

Role: `admin`. The signing secret is generated by the Hub and **shown once**. Agree the tenant, endpoint id and URL with the user first.

URL rules: the host must be on the admin's allowlist (`HUB_CALLBACK_HOSTS`), and the SSRF guard resolves it and refuses private or link-local addresses (400 `VALIDATION_FAILED`). The MCP tool accepts only `https://` URLs. Deliveries do not follow redirects and time out after 5 s.

- **Console:** Tenants → *tenant* → Callback endpoints → **Register endpoint** → endpoint id, URL, description, reason. The secret appears once (**Copy**, then **Done**).
- **hubctl:** not supported (`apply` refuses registrar endpoints). Local dev only: `backend/config/registrar/<id>.yaml` plus `hubctl creds set <id> signing_secret=<at least 16 bytes>`.
- **MCP:** after the user agrees:
  ```json
  hub_admin_create_registrar_endpoint {
    "endpoint_id": "reg_orders_cb", "tenant_id": "orders-service",
    "url": "https://orders.internal/hub/callbacks", "description": "Orders callbacks",
    "reason": "Callbacks for async integrations", "confirm": true
  }
  ```
  Give `signing_secret` to the user once, verbatim, to store in their secret manager. Never repeat it or pass it to another tool.
- **Admin API:** `POST $HUB_ADMIN_URL/admin/v1/registrar-endpoints` with `{"endpoint_id", "tenant_id", "url", "description", "reason"}` (`createRegistrarEndpoint`); the response holds `endpoint` and `signing_secret`.

## Subscribe an integration to events

Events: `request.completed`, `request.failed` (dead-lettered), `request.expired` (TTL passed), `delivery.status` (non-terminal changes such as parked). Add them to the version spec and publish ([cutover.md](cutover.md)):

```json
"webhooks": [
  {"event": "request.completed", "endpoint_id": "reg_orders_cb"},
  {"event": "request.failed",    "endpoint_id": "reg_orders_cb"},
  {"event": "request.expired",   "endpoint_id": "reg_orders_cb"}
]
```

(In registry YAML files the key is `endpoint:` instead of `endpoint_id:`, e.g. `backend/config/integrations/int_evt_brandB/versions/1.yaml`.) Publishing `async_callback` without a subscription fails validation (`delivery_path_declared`).

## What the tenant receives and how to verify it

```http
POST /hub/callbacks
X-Hub-Signature: t=1793438102,v1=<hex HMAC-SHA256(secret, t + "." + raw_body)>
X-Hub-Event: request.completed
X-Hub-Delivery-Id: dlv_01J9Z5D4E5F6G7H8J9K0M1N2PQ

{"event_id": "evt_...", "type": "request.completed", "integration_id": "int_evt_brandB",
 "operation": "default", "request_id": "req_...", "idempotency_key": "order-8821-created",
 "data": {"status": "succeeded", "result": {...canonical response...}, "attempts": 1}}
```

The receiver must:
1. Compute the HMAC over the **raw body bytes** before parsing JSON; compare in constant time; accept any `v1` (during a secret rotation the header carries two).
2. Reject `t` more than 5 minutes from now.
3. Deduplicate by `X-Hub-Delivery-Id` / `request_id` (delivery is at least once).
4. Answer 2xx within 5 s; do slow work afterwards.

Copy-paste verifiers (Go, Python, Node) are in the consumer skill: `clients/claude-skill/integration-hub/SKILL.md`, section "Callbacks". Payload schemas: `contracts/schemas/events/`. Callbacks have their own retry schedule and dead-letter queue; a failing receiver never changes the request's own status (use case 4 in `docs/use-cases/README.md`).

## Change the URL, rotate the secret, disable, delete

| Action | Console (tenant → Callback endpoints) | MCP | Admin API |
| --- | --- | --- | --- |
| Change URL or description (live traffic) | **Edit** | `hub_admin_get_registrar_endpoint`, show old and new URL, then `hub_admin_update_registrar_endpoint {"endpoint_id", "url", "reason", "if_match", "confirm": true}` | `updateRegistrarEndpoint` |
| Rotate the signing secret with overlap (both secrets sign until the overlap ends) | **Rotate secret** | — (never: mints a secret) | `rotateRegistrarSecret` |
| Disable / enable | **Disable** / **Enable** | — (never: kill switch) | `updateRegistrarEndpoint` with `disabled` |
| Delete | **Delete** (role `admin`) | — (never: no delete tools exist) | `deleteRegistrarEndpoint` |

Before deleting, remove the endpoint from every integration version that subscribes to it (publish new versions); the endpoint shows `subscribed_by`.
