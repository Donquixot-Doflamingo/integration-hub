## What was built
- **Queue** (HUB-110): `hub.outbox` (pool column, partial claim / parked / reclaim / TTL / ordering indexes, fillfactor 70) and `hub.dead_letters`; `queue.Outbox` on the caller's transaction: Enqueue / EnqueueClaimed, Claim (`SKIP LOCKED`, visibility, reclaim with crash count), Ack, Nack, Defer, Park, Release (arrival order), DeadLetter, Expire, Replay.
- **States** (HUB-111): `core.State` with the §10.9 transition table; every transition is a compare-and-set on status + claim; a lost race writes nothing.
- **Shared attempter**: `delivery.Attempter` runs transform → credentials → upstream → classify → map for sync, wait and worker attempts (TECH_SPEC §4.2).
- **Worker** (HUB-112/113): claim, poison, TTL, paused hold, re-resolve (D10; pinned and sessions keep their version), re-transform, attempt rows with the version used; backoff +1 s … +1 h (8 attempts, full jitter, Retry-After floor); retry budget 20 % of live traffic per account; rejections, auth failures and transformer errors dead-letter at once with the last request/response (policy-applied).
- **Scheduler** (HUB-114): advisory-lock leader with polling standby; TTL expiry; hourly pruning of dead letters (14 days) and kept results (7 days).
- **Edge modes** (HUB-115/116): async 202 only after commit; wait persists claimed by the gateway, attempts at once, 200 / canonical error within `wait_ms` or 202 `in_flight` while the gateway finishes; interactive capabilities stay sync; `GET /v1/requests/{id}` (tenant-scoped, live outbox state, kept result).
- **Audit** (HUB-117): persisted / policy.applied / accepted at accept; each attempt in its own block (seq attempt×100) closed by completed / retry.scheduled / dead_lettered from the winner only; terminal record, status, result and callbacks commit in one transaction; `queue_wait_ms` on the final record.
- **Idempotency** (HUB-118, agent): Redis store (Lua, lease 5 min, 24 h from first claim, header allowlist, 1 MiB cap), wired in the edge: replay with `X-Hub-Idempotent-Replay` and the original request id, 409 on body mismatch, the original 202 for queued duplicates, release on every non-replayable outcome, fail closed for `moves_money_or_quota` when Redis is down.
- **Callbacks** (HUB-119/120, agent; HUB-121): SSRF-guarded sender (dialed-IP check, no redirects, 5 s), signing with rotation overlap, `hub.callback_deliveries` with its own retry schedule and DLQ, dispatcher in the worker; terminal events enqueued in the terminal transaction.
- **Roles**: `hub worker --pool`, `hub scheduler` and the gateway's queueing and idempotency are wired; Redis client fails fast.

## Deferred
- **Per-integration retry schedule override** (DESIGN §10.3 "overridable per integration"): the registry has no field yet → **HUB-124**.
- **Parking and drain** on an open circuit (Park / Release exist; `request.parked` is unused): M5 (HUB-146, HUB-149).
- **`delivery.status` callbacks** on non-terminal transitions: the event type and enqueue support exist; not emitted yet.
- **Queue metrics** (`queue_depth`, `worker_inflight`, `outbox_claim_duration_seconds`): HUB-230.
- **DLQ replay through the admin API**: `queue.Outbox.Replay` exists; the endpoint is EP-08 (HUB-209).
- **Purge of delivered callback rows** (their payload is stored in clear for retries): open question in F-11.

## Deviations
1. **Final results for polling live in `hub.request_results` (7 days)**, separate from the audit payloads, so `GET /v1/requests/{id}` returns `result` even when the integration's audit policy is `metadata_only`. The audit policy still governs history. See open question 1.
2. **The wait-mode gateway attempt does not use the sync immediate retry**; a retryable failure is scheduled on the backoff schedule (first step ≤ 1 s) and the caller gets 202.
3. **Audit sequence numbers are blocks**: accept 1…n, attempt k k×100…, callbacks 1 000 000+ (agent). `seq` orders the timeline; gaps between blocks are expected (the M3 gap-free check applies to sync requests).
4. **Retry budget is per process** (in memory), not shared across worker nodes; with N workers an account can get up to N × burst retries before the 20 % ratio applies. Shared state comes with the Redis account limiter (M5).
5. **`internal/idempotency` is its own package** (DESIGN §18.1 puts idempotency inside `edge`); recorded in ADR-0001.
6. **Callbacks go only to endpoints of the requesting tenant** (registry ties subscriptions to the owner), so a grantee's requests get no callback (F-11 open question).
7. **A paused integration's queued envelopes are held 30 s at a time without spending an attempt** (`queue.Defer`).

## Open questions for the user
1. Should `GET /v1/requests/{id}` return the result for integrations whose audit policy is `metadata_only` or `sealed` (deviation 1), or only status and error?
2. Retention of delivered callback rows and of the callback DLQ.
3. Callback host allowlist: per tenant or global?
