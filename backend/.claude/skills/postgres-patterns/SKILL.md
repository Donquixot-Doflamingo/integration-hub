# Postgres patterns

Postgres 16. Driver `github.com/jackc/pgx/v5` (`pgxpool`), queries generated by `sqlc`, migrations by `goose` in `backend/migrations/`. Data model: DESIGN §18.2. Full SQL examples: [references/queries.md](references/queries.md).

## Ownership
Each adapter package owns its tables and queries (`internal/queue/postgres` → `outbox`, `dead_letters`; `internal/audit` → `requests`, `request_events`, `request_attempts`; `internal/control` → registry tables, `change_log`). No package queries another package's tables; go through its port.

## Pools and connections
```go
cfg, err := pgxpool.ParseConfig(string(dsn))
if err != nil { return nil, fmt.Errorf("parse dsn: %w", err) }
cfg.MaxConns = int32(opts.MaxConns)         // per pod; see budget below
cfg.MinConns = 2
cfg.MaxConnIdleTime = 5 * time.Minute
cfg.MaxConnLifetime = 30 * time.Minute     // rotate through failovers
cfg.ConnConfig.RuntimeParams["application_name"] = "hub-" + role
cfg.ConnConfig.RuntimeParams["statement_timeout"] = "5000" // ms; per-role
pool, err := pgxpool.NewWithConfig(ctx, cfg)
```
- Connection budget: `sum over roles (replicas × MaxConns) + admin/migrations headroom ≤ max_connections × 0.8`. Workers need ≈ claim loops + audit writer, not one per in-flight vendor call (no transaction spans a vendor call).
- If PgBouncer is introduced in **transaction** pooling mode: session advisory locks (scheduler leader) and session `SET`s break; the leader uses a direct connection. Prepared statements need pgx's `QueryExecModeCacheDescribe`/`Exec` modes — decide in an ADR.
- Always pass `ctx`; set `statement_timeout` per role (gateway short, admin longer). The sync path never touches Postgres; wait/async only to insert the envelope.

## sqlc conventions
- One `queries/*.sql` per table group inside the adapter package; generated code in `<adapter>/db` (never edited by hand).
- Names: `-- name: ClaimOutbox :many`, `:one`, `:exec`, `:execrows` (use for CAS: returns rows affected).
- Named args: `sqlc.arg(worker)`, nullable `sqlc.narg(reason)`. Cast intervals/arrays explicitly (`sqlc.arg(visibility)::interval`, `sqlc.arg(ids)::text[]`).
- `sql_package: pgx/v5`; override `jsonb` → `encoding/json.RawMessage`, and non-null `timestamptz` → `time.Time`.
- Wrap generated calls in a small adapter type that implements the port and converts db structs to domain types; generated types never leak out of the adapter.
- `sqlc vet` / `sqlc compile` in CI against the migrated schema.

## goose migrations
- Location `backend/migrations/`, created with `goose -dir migrations create <snake_name> sql` (timestamp prefix avoids merge collisions). One concern per migration.
- Every file has both sections:
```sql
-- +goose Up
CREATE TABLE ...;
-- +goose Down
DROP TABLE ...;
```
Use `-- +goose StatementBegin/StatementEnd` around functions/`DO` blocks; `-- +goose NO TRANSACTION` for `CREATE INDEX CONCURRENTLY`.
- **Never edit a migration that has been applied anywhere (merged to main).** Fix forward with a new one.
- Online-safe changes: add nullable columns, then backfill in batches, then add constraints `NOT VALID` + `VALIDATE CONSTRAINT`; `CREATE INDEX CONCURRENTLY` on big tables; never rewrite `requests`/`request_events` in one statement.
- Migrations run as a separate step (`hubctl migrate` or a k8s job), never implicitly at gateway start.

**Schema-qualify everything.** Migrations live in `backend/migrations` (embedded, applied by `hub migrate`). The dev/CI role is named `hub`, and the default `search_path` is `"$user", public`, so once schema `hub` exists an unqualified name silently resolves to `hub.<name>`. This made goose re-run migrations on fresh databases (fixed in HUB-023: the version table is pinned to `public.goose_db_version`). Write `hub.outbox`, never `outbox`, in DDL and in sqlc queries. Test migrations on a **fresh** volume (`docker compose down -v`), not only on an already-migrated one.

## Partitioning (requests, request_events, request_attempts)
- `PARTITION BY RANGE (created_at)` by day. The partition key must be part of every PK/unique constraint: `PRIMARY KEY (request_id, created_at)`.
- Put the **request's** `created_at` on its events and attempts too (column `request_created_at`), so a request's whole timeline lives in one day partition even if events arrive days later (AA flows). Request ids are ULIDs (`req_01J9…`): the timestamp in the id gives the partition bound, enabling pruning on lookups by id.
- A scheduler job creates partitions ≥ 3 days ahead and detaches/drops expired ones (hot 30 days, sealed 90, §13.4) after export to object storage. `DROP`/`DETACH PARTITION`, never `DELETE` for retention. Alert if tomorrow's partition is missing.
- No default partition (it hides missing-partition bugs and makes attaching slow).

## Outbox
Columns per §18.2 plus `attempt`, `claim_count`, `created_at`. Indexes (partial, matching the claim predicates exactly):
```sql
CREATE INDEX outbox_due      ON outbox (next_attempt_at) WHERE status IN ('accepted', 'retry_scheduled');
CREATE INDEX outbox_inflight ON outbox (claimed_until)   WHERE status = 'in_flight';
CREATE INDEX outbox_parked   ON outbox (account_id, endpoint_id, created_at) WHERE status = 'parked';
```
Keep the table small: terminal rows leave the outbox (the ledger is `requests`); autovacuum tuned aggressively for it (`autovacuum_vacuum_scale_factor = 0.01`).

## Claim with SKIP LOCKED (visibility timeout)
```sql
-- name: ClaimOutbox :many
WITH due AS (
  SELECT request_id FROM outbox
  WHERE (status IN ('accepted', 'retry_scheduled') AND next_attempt_at <= now())
     OR (status = 'in_flight' AND claimed_until < now())        -- reclaim from dead workers
  ORDER BY next_attempt_at
  LIMIT sqlc.arg(batch)
  FOR UPDATE SKIP LOCKED
)
UPDATE outbox o
SET status = 'in_flight', claimed_by = sqlc.arg(worker),
    claimed_until = now() + sqlc.arg(visibility)::interval,
    claim_count = o.claim_count + 1
FROM due WHERE o.request_id = due.request_id
RETURNING o.*;
```
If the `OR` defeats the partial indexes in `EXPLAIN`, split into two claim queries (due, then expired claims). Poison: `claim_count` beyond the threshold without a recorded attempt → dead-letter.

## Compare-and-set transitions
```sql
-- name: TransitionStatus :execrows
UPDATE outbox
SET status = sqlc.arg(to_status), next_attempt_at = coalesce(sqlc.narg(next_attempt_at)::timestamptz, next_attempt_at),
    claimed_by = NULL, claimed_until = NULL
WHERE request_id = sqlc.arg(request_id) AND status = sqlc.arg(from_status) AND claimed_by = sqlc.arg(worker);
```
0 rows → lost the race → no side effects. Terminal transitions update `requests.status`, write the final audit record and enqueue the callback **in one transaction**.

## Transactions and isolation
```go
err := pgx.BeginTxFunc(ctx, pool, pgx.TxOptions{IsoLevel: pgx.ReadCommitted}, func(tx pgx.Tx) error {
	q := db.New(tx)
	if err := q.InsertRequest(ctx, ...); err != nil { return fmt.Errorf("insert request: %w", err) }
	return q.InsertOutbox(ctx, ...)
}) // commits on nil, rolls back on error or panic
```
- Default **Read Committed**; claims and CAS are correct under it.
- Publish pipeline (new integration version + active pointer + snapshot row): lock the integration row (`SELECT ... FOR UPDATE`) or use Serializable with a retry loop on SQLSTATE `40001`/`40P01`.
- Never hold a transaction across network I/O (vendor, Redis, KMS).
- Error handling: `errors.Is(err, pgx.ErrNoRows)` → domain `ErrNotFound`; `var pgErr *pgconn.PgError; errors.As(err, &pgErr)` and switch on `pgErr.Code` (`23505` unique violation → idempotent insert / conflict, `40001` retry).

## Advisory locks
- Scheduler leader: `pg_try_advisory_lock(<const int64>)` on a **dedicated** connection (session lock; released when the session ends). Code in `go-system-design/references/patterns.md`.
- Short critical sections inside a transaction: `pg_advisory_xact_lock(hashtextextended(<key>, 0))` (released at commit) — e.g. per-account retire check vs new pinned request.
- Document every lock key constant in one Go file.

## JSONB
- Use for documents read whole: `integration_versions.spec`, `outbox.envelope`, `config_snapshots.diff`, `change_log.before/after`.
- Anything you filter, join or index on is a real column (status, account_id, endpoint_id, tenant, expires_at), not a JSON path.
- Audit payload bytes go to `bytea`/object storage refs with `sha256` and `bytes` columns (§13.3); don't store large payloads as JSONB (re-encoding changes bytes; "lossless" needs exact bytes).

## Testing
- Migration round trip: up → down to 0 → up (integration test).
- Query tests against real Postgres (testcontainers, `go-testing`): claim concurrency (N workers, every row claimed once), reclaim after visibility timeout, CAS lost race, partition routing for a request at 23:59:59 UTC.
- `EXPLAIN` assertions for the claim query in an integration test (it must use `outbox_due`) to catch index regressions.
