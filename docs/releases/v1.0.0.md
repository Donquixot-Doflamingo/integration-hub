**Status:** draft, not tagged. Tag per `docs/process/RELEASE.md` once the blockers below are closed (or accepted as known issues).
**Scope:** DESIGN §19 M0 to M8, the admin console (EP-10), the MCP server (EP-11) and the first Release-2 pieces (per-operation transformers, the use-case catalogue).

## What callers get
- One endpoint per integration: `POST /v1/integrations/{id}/invoke`, with a canonical body in and a canonical response or error envelope out. Vendor, account and version never appear (D2, D12).
- Delivery modes `sync`, `wait` (default, 3 s window), `async` and `async_callback` with signed callbacks; idempotency keys; caller dry-run behind the `dry_run` scope.
- **Multi-step flows on one integration ID** (new): `POST /v1/integrations/{id}/invoke/{operation}`, for example `send_otp` then `verify_otp`. Each operation has its own transformer pair and vendor endpoint, and the vendor session carries between steps in `X-Hub-Session`. See `docs/use-cases/README.md` and `examples/otp-account-flow/`.

## What operators get
- **Resilience:** circuit breakers per (account, endpoint) shared through Redis, `fail_fast` on sync, parking and a ramped drain (20 % → 40 % → 80 % → 100 % of the account rate), rate limits and bulkheads.
- **Versioning and cutover:** integration versions with weights, shadow traffic and rollback; pending work re-resolves at send time (D10); account lifecycle and credential rotation with overlap.
- **Control plane:** the admin API (79 operations, RBAC, change log), `hubctl` (export, plan, apply, dry-run, replay), and the SvelteKit console.
- **Observability:** §16.2 metrics, OTel traces from caller to callback, ten alert rules with runbooks (`docs/runbooks/`), and three dashboards.
- **Security:** blocking gosec and govulncheck gates, Go toolchain go1.26.10, `sealed` audit with audited unseal for bureau, Aadhaar and PAN data, value-based log redaction, SSRF guard on callbacks, a TLS 1.2 floor.
- **MCP server** (`hubmcp`): stdio and streamable HTTP; discovery, invoke, status, dry-run and read-only admin tools; a confirm guard for integrations that move money or quota.

## Measured (laptop scale, mockvendor; `docs/tech/LOAD_TEST_REPORT.md`)
- The Hub adds about 1.1–1.4 ms at p50 and 2.5–3.5 ms at p99 to a sync call.
- 500 sync RPS with 0 errors, server overhead p99 3.8 ms.
- Soak: 42,000 async messages over 5 vendor outages: 0 lost, 0 duplicate callbacks.

## Known issues (not blocking)
- The account limiter makes a Redis call on every sync request and adds about 2.7 ms at p99 under load (HUB-408).
- Audit masking runs on the request goroutine, 20–27 % of gateway CPU at 500 RPS (HUB-409); the audit writer drops a whole batch on one failed write (HUB-410).
- The Grafana import check for dashboards is not automated (HUB-243).
- hubctl lacks on-call commands for breakers, pause, DLQ list and rotation; the runbooks use curl (HUB-400).
- The admin API does not enforce the credential minimum length (HUB-402).

## Upgrade notes
First release; no upgrade path. Migrations are append-only (goose), and the pre-deploy job applies them.
