## What was built
- **Breaker** (HUB-140/141): `upstream.Breaker` (weighted rolling window, consecutive timeouts, doubling open window, half-open probes) and `upstream.Breakers` (Redis `SET` + `PUBLISH hub:breaker`, 1 s reconcile, pending states for unused breakers, never on the request path).
- **Admission** (HUB-142/144/147): in `delivery.Attempter` before every vendor call: shared breaker, integration override view, account limiter; outcomes recorded with TECH_SPEC §10 weights.
- **`on_circuit_open`** (HUB-144/145): fail_fast, failover (safe repeats only, audit per target), queue_if_allowed (park with `Prefer: respond-async` or a subscription).
- **Parking** (HUB-146): wait → 202 queued at once; worker parks without spending an attempt; arrival order.
- **Probes and drain** (HUB-143/149): scheduler leader probes open breakers and ramps releases 20/40/80/100 %.
- **Limits** (HUB-147/148): Redis token bucket per account (live first), tenant + integration bucket at the edge, per-account bulkhead (64, from M3).

## Deviations
1. **Health probes carry no credentials**: an auth error proves the vendor answers, so any answer below 500 except 429 counts as healthy. This keeps secrets out of the scheduler.
2. **A trip within `OpenMax` of a recovery counts as a re-open** (doubled window), not only a failed half-open probe; DESIGN's "doubling per re-open" applied to flapping vendors (HUB-152).
3. **The tenant limiter is per gateway node** (in memory): the fleet-wide limit is rps × nodes. The account limiter is shared.
4. **Failover also triggers on `UPSTREAM_UNAVAILABLE` / `UPSTREAM_TIMEOUT` answers**, not only on an open circuit (TECH_SPEC §10 sync column "failover if configured").
5. **Dry-run is exempt from the tenant limiter** (no vendor call).
6. **`ratelimit_rejections_total` has only the `layer` label** (the catalogue also lists tenant and integration); cardinality stays bounded until HUB-230 decides.
7. **Drained and retried envelopes are not "live"** for the account limiter: they leave a 20 % reserve to caller traffic.
