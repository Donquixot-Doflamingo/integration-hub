## What was built
- **Edge server** (HUB-080): `req_` ULID on every response and in the log context, panic → 500 envelope (no body in logs), `WriteError` with `Retry-After` for 429/503; every canonical code validated against the contract.
- **Tenant auth** (HUB-081): hashed keys from the snapshot, constant-time compare, revoked → 401, suspended → 403; grants and scopes (`<scope>` or `<scope>:<integration>`).
- **Body limit and validation** (HUB-082): 1 MB / 4 MB (`llm.*`), refused from `Content-Length` before reading; one detail per violation with its JSON pointer.
- **Resolver** (HUB-083): active or exact version, sticky weighted target (FNV of idempotency key or request id).
- **Credentials** (HUB-084/085, by the backend agent): AES-256-GCM local file, warm cache that never decrypts on the request path, `hubctl creds`; static_headers, bearer and basic schemes applied after the transformer.
- **Upstream client** (HUB-086, by the backend agent): one pool per account, endpoint and connect timeouts, caller deadline, egress allowlist (declared regions only), typed transport errors, `vendor_latency_ms`.
- **Outcome classification** (HUB-087): transport errors → 504/503, sync retry once after timeout/reset only when idempotent or keyed, Retry-After and the vendor's message/code enrichment.
- **Invoke** (HUB-088): `/invoke` and `/invoke/{operation}`, paused, Idempotency-Key required for `moves_money_or_quota`, `X-Request-Deadline`, `X-Hub-Served-By`, debug-only `X-Hub-Integration-Version` (`HUB_DEBUG_HEADERS`).
- **Dry-run** (HUB-089): exact upstream request with credentials and scheme headers as `***`, `redacted` paths, audited with `dry_run`, zero vendor calls.
- **Discovery** (HUB-090): list (owned or granted, filter, cursor), describe, capability schemas; no vendor, account or version anywhere (leak test); not granted is 404.
- **Audit** (HUB-091/092/093): day-partitioned `requests`, `request_events`, `request_attempts` (partitions 7 days ahead); non-blocking writer with drop counter and fill gauge; per-request `Trail` with sha256 + size of the bytes seen; `full`, `masked` (x-pii by pointer and by value, per-tenant HMAC), `metadata_only`; credential values redacted from every stored payload.
- **SDK** (HUB-094, by the backend agent): `pkg/hubclient` with sealed `Result`/`Queued`, typed `*Error`, discovery, dry-run and request status.
- **Gateway role**: `hub gateway` mounts the edge; credentials warmed before every snapshot swap; audit writer drained after the listeners close.
- **Tests** (HUB-095/096/097): the e2e and audit checks above, the overhead benchmark, contract validation of every exchange in the edge tests (`contract.Spec.Serve` / `ServeInvalid`).

## Deferred
- **Object-storage spill** of audit payloads over 64 KB: stored truncated (`payload_state = truncated`) → HUB-098.
- **Sealed policy**: stores no bodies until field-level encryption (HUB-208).
- **Breaker, account limiter, bulkhead, tenant rate limit**: M5 (EP-06); the `admission` and `rate_limit` stages are not recorded yet.
- **Idempotency replay** (Redis) and the 202 paths: M4 (HUB-115/116/118).
- **`/readyz` waiting for credential warm-up**: today warm-up runs before the snapshot swap and failures are logged; accounts that failed answer 503 `credentials_unavailable`.
- HUB-031 follow-up from contract round 1: validate the live `/readyz` 503 body against hub-public 1.0.1.

## Deviations
1. **Every delivery mode is delivered synchronously in M3.** `wait`, `async` and `async_callback` integrations get a 200 or a canonical error, never a 202, until the outbox lands (M4, HUB-115/116). This is milestone sequencing, not a design change.
2. **Dev credential file location**: `.data/dev-secrets.enc` and `.data/dev.key` (git-ignored), not `config/` as TECH_SPEC §8.1 said, because every file under `config/` is packed into snapshot blobs and the checksum. TECH_SPEC §8.1 updated.
3. **Gateway without a credential key file starts** (warning) and every vendor call fails closed with 503 `credentials_unavailable`, so dev and tests can run the gateway without secrets.
4. **`HUB_AUDIT_MASK_KEY` unset → random key per process** (warning): masked identifiers are then not stable across restarts. Production must set it (≥ 32 bytes).
5. **Calls rejected before authorization** (401, unknown or not-granted integration) are not audited: there is no tenant-owned integration to attach them to. They are logged and counted.
6. **Span name** is `upstream {vendor}.{endpoint}` where OBSERVABILITY §5.1 says `hub.upstream`; `vendor_latency_ms` uses the label `outcome` (status class or transport kind) instead of `code`, because the upstream package does not know canonical codes. To settle in HUB-230 (metrics) — the doc row was updated for the label.
7. **getIntegration answers 404 for a not-granted integration** (F-05 rule 3, no enumeration), while invoke and dry-run answer 403 `not_granted` (HUB-081).
