## What was built
- **Parser** (HUB-060): YAML sections become target trees with paths like `request.body.d[0].evtName`. Duplicate, conflicting and unknown keys are rejected.
- **Compiler** (HUB-061): expr-lang 1.17.8, compiled once (with a counter-tested guarantee).
  - `req.*` paths are checked against the capability JSON Schema.
  - Each direction has its own variables.
  - `creds.*` is allowed only in headers and query unless `allow_creds_in_body`.
  - Only the DESIGN §7.3 built-ins are allowed.
- **Standard library** (HUB-062/063): all DESIGN §7.3 functions; `now()` and `uuid()` are injectable for deterministic goldens.
- **Request mapping and dry-run** (HUB-064): dry-run is the exact request with credential-derived values masked.
- **Response and error mapping** (HUB-065):
  - Error rules are ordered and the first match wins.
  - Unmatched 4xx/5xx are classified by status, never mapped as success.
  - Output is validated against the capability response schema.
  - `EvalError` (→ TRANSFORM_FAILED) never contains input values.
- **Budgets** (HUB-066): depth, nodes, memory, output size and time.
- **Goldens** (HUB-067): `transform.RunGoldens`, JSON-pointer diffs, `hubctl transform test` (exit 0/1/2), `make goldens`.
- **Transformers** (HUB-068): T1, T2, R1 and R2 checked against the CleverTap Upload Events API docs and cited in each file, with 17 goldens.
- **Snapshot integration** (HUB-069): every transformer is compiled and golden-tested at snapshot build, and the compiled programs are shared.
- **Benchmark** (HUB-070): recorded in TECH_SPEC.

Coverage (unit): `internal/transform` 83 %, `internal/registry` 82 %, `cmd/hubctl` 76 %.

## Deviations
| # | Deviation | Why | Recorded |
| --- | --- | --- | --- |
| 1 | Every `a.b` compiles as `a?.b` (nil-safe), and nil object fields are not sent | DESIGN's own `req.context.campaign ?? "organic"` would otherwise fail when `context` is omitted; optional canonical fields are common | `compile.go`, hub-transformers skill |
| 2 | `res.body` holds only parsed JSON (object, array or scalar); a non-JSON body (HTML error page) is `res.text` | Field access on an HTML 503 would otherwise throw and turn an outage into TRANSFORM_FAILED | `response.go`, skill, R1 golden |
| 3 | YAML syntax constraints: expressions with `: `, ` #` or `{` after `map(x,` must be quoted or parenthesised | YAML comments and the expr parser; found on the dev transformers | skill (YAML quoting) |
| 4 | Expression depth is measured as bracket nesting (limit 24), plus a 500-node AST limit | expr's AST walker gives no parent or child access for a true depth | `compile.go` |
| 5 | The time budget is bounded by construction (VM memory budget 100 k, node and depth limits) and checked after each run, not pre-emptively. The wall-clock test runs without `-race` | expr-lang cannot pre-empt (ADR-0002); the race detector slows the VM about 10× | `limits.go`, Makefile |
| 6 | `formatTime` zones are `UTC` or fixed offsets only | IANA zones read zoneinfo from disk; transformers are pure | `stdlib_text_time.go` |
| 7 | `flatten`, `toJSON` and `fromJSON` are Hub implementations (flatten objects to dotted keys; compact sorted JSON), not expr's built-ins | Deterministic output for signatures and goldens; DESIGN's `flatten` is about objects | `stdlib_data.go` |
| 8 | The four dev transformers were corrected in place (charset, R1 `rejected` mapping, a 503 "account ID" rule) instead of becoming new versions | Never published anywhere; versions are immutable once published | HUB-068 commit |
| 9 | Fixture layout is `transformers/<id>/<version>.yaml` + `transformers/<id>/fixtures/` | Matches the M1 dev config (TECH_SPEC §8.2); the skill already says to follow the existing layout | `golden.go` |
